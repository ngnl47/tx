### 2026-09-12 NATS 与本地 Actor 运行时分支试验

三个工程均在 `feature/nats-actor-runtime`；T3a–T3g 及归属设计已提交，本轮 I1 起点 tx=8de6005，六工程工作区干净。本轮累计完成 tx 的 I1 归属组合测试和 I2 完整上行业务对照，修复试验区的信封模式标记，未迁移正式运行时。[T1–T2d](audits/2026-09-12-nats-actor-runtime-trial.md) 保留原型正确性证据；[T3a](audits/2026-09-12-nats-shared-replies.md) 收敛共享响应与失败清理，[T3b](audits/2026-09-12-nats-aggregate-throughput.md) 完成多实例聚合评估，同机三 broker 未反超，固定到达率业务预算未确认。

[T3c 分层归因](audits/2026-09-12-nats-layered-cost.md) 已完成：官方 128B Pub/Sub 订阅速率中位数约 99.5 万条/s；108 个 RPC 窗口完成 721.83 万次调用、0 返回错误。三端 profile 指向调度同步开销，单变量五轮复测中，将测试进程 GOMAXPROCS 从 4 改为 1，完整 NATS 吞吐从 1.50 万提高至 2.42 万次/s（+61.4%）；同配置 ProtoActor 为 3.09 万。结果证明配置影响明显，不是 NATS 通用容量上限，但仍未达到既定筛选线。**T4 正式替换继续暂停**，保留 Core 候选，不修改生产默认值，不继续空回显的零碎微优化。后续按用户确认先进行下述链路差异对照；GD/Procedure 代表业务与预算仍待评估。正式 GD/实例租约接线、示例迁移和 JetStream 均未完成，公共行为继续以现行 README 为准。

[T3d 链路差异](audits/2026-09-12-nats-rpc-path-differences.md) 已完成三组五轮对照及独立写入诊断：单 P、64 并发下，ProtoActor 关闭消息批处理后吞吐下降约 38%，分配从约 49 增至 113 次/RPC；当前 NATS 两端几乎逐消息 Write，四 P 时会合并到约 3 条/次。固定回复主题虽大幅减少了订阅树匹配，省去 Receive context/Future 也减少了分配，但均没有稳定吞吐收益，因此不改运行时。固定发送协程的后续验证见 T3e。

[T3e 固定发送协程](audits/2026-09-12-nats-fixed-sender.md) 已完成 60 个正式窗口和 8 个独立写入诊断窗口：单 P、64 并发的消息/Write 提高到约 63～64，但吞吐中位数下降 28.2%；四 P、64 并发吞吐提升 18.8%，五轮均提高，P99 中位数下降 19.4%。每 RPC 多约 6 次分配、0.5KiB，CPU/RPC 降低；这是局部收益，不能覆盖单 P 退化，因此不接入运行时或新增条件配置。不继续微调本批发送队列。T4 继续暂停，既定筛选线不变。

[T3f 请求封包实验](audits/2026-09-13-nats-request-batch.md) 已完成隔离候选、真实依赖 race 及三组五轮对照：314.51 万次正式 RPC 无返回错误，诊断另计 76.05 万次。单 P 实际约 1 项/包，吞吐中位数 -4.7%、P99 +14.2%；四 P 约 2.91 项/包，消息数减少 32.8%，吞吐仅 +3.2% 且五轮有升有降。没有稳定收益，不接入默认运行时，不继续双向合批或调参；保留独立 Reply、批次错误清理和排水边界的测试证据。随后用户已确认传输分工与共用路由，并批准下述 T3g；T4 正式替换门槛尚未改写。

[T3g 共用路由与直连上行](audits/2026-09-13-actor-shared-routing.md) 内部节点已完成：复用 SlotResolver、rpc Host/Sender 和同一个 Runtime，直连 Agent 完成 ACK 与 NATS Actor Call 共用归属、邮箱和排水。该批真实交接及 race 通过，tx 全量测试 1147 pass / 61 skip；正式示例未迁移。五轮缓存路由中位 187.5ns、8B/1 alloc，1KiB 单机顺序直连 Call 约 151μs、199 alloc，不作为跨机吞吐承诺，也不是本轮验证。

T3h 的 [归属组件设计](superpowers/specs/2026-09-13-actor-ownership-design.md) 与 [接线计划](superpowers/plans/2026-09-13-actor-ownership-integration.md) 已提交到 `8de6005`。本轮完成 [I1 事务写回与租约组合验证](audits/2026-09-13-actor-ownership-integration.md)：真实 Redis 写回失败保留待刷根、响应未知不晋升，显式重试后新 owner 读到最后值；真实租约撤销后双入口关闸且不自动改派。定向 race 12 pass；tx 全量 1147 pass/63 skip，真实依赖试验包 71 pass/1 性能入口 skip。以上为 I1 验证记录。随后完成 [I2 完整上行评审](audits/2026-09-13-uplink-business-comparison.md)：使用现有生成 Redis GD、真实 Procedure/writeback 和完整 Session/MsgQ 链路，修复原型 Call/Tell 信封标记。1 KiB 中位完成吞吐为 ProtoActor 5661/s、hybrid 4642/s、NATS 4264/s；hybrid 的 broker 收发字节比全 NATS 低约 96.2%。用户已接受 I2 临时业务预算并允许进入 I3；[I3a](audits/2026-09-13-framework-handoff-preparation.md) 已完成正式 PrepareHandoff、控制 RPC/CLI、Stop 共享收尾及固定基线记录。下一项继续权威槽位访问和实体宿主迁入，原 10% 比较线作为偏移排查提示保留。两个示例及 Mongo/Fusion 仍待 I4 验收。

## 待决策能力

下列事项在进入实现前必须重新评审需求、边界和成熟依赖，不能以占位配置或兼容接口提前进入主线。

### 外部业务配置生成

txgame 当前使用项目维护的类型化配置最小契约；txgameslg 的 Login 列表从项目资产加载。
后续扩展 txgen 的外部配置生成前，需明确 Excel 输入、类型推导、JSON 输出与加载契约；两套示例分别生成和维护，不相互引用。

### getter 触发的懒加载

当前已加载字段状态只描述读取结果，getter 不执行 I/O。若要支持 getter 懒加载，需要先确定：

- loader 由谁持有，是否允许数据对象依赖运行时；
- getter 如何返回 I/O error；
- Actor、Procedure 和普通请求三种所有权边界下是否允许隐式读取；
- 并发加载、失败重试和部分字段定位如何保持一致。

在这些问题决策前，不生成隐式 I/O getter。

### 可靠业务消息

可靠任务需要发布确认、业务执行后确认、重试与死信处置；已接受成功后结果/ACK 丢失的重复窗口，不建设完成表或要求 GD 记录幂等字段。`modules/msgq` 是客户端会话邮箱，它不能代替可靠业务消息。

按上述试验计划验证 JetStream；永久加载拒绝转死信，业务明确无法处理并结束任务则确认，暂时故障重试。ACK 不等待 GD 刷盘。MQ 产品最终采用以真实链路验证为准。

### 控制面认证与 TLS/mTLS

当前控制面和内部 gRPC 只要求调用方显式选择 TLS credentials 或本地 insecure。生产认证、证书加载、轮换和权限模型尚未实施。后续设计必须保持 `Sender`、`Delivery`、`Drain` 和槽位交接的业务 API 稳定，并优先适配本地研发与云私网部署。

### 异常接管与执行者归属

逻辑槽位支持受控排水后的 generation CAS 交接；Mongo 文档版本只拒绝已经过时的写入基线，不识别实例或槽位，也不能阻止错误路由的执行者重新读取版本后发起新写入。
异常宕机、网络分区和自动接管的通用租约与调度策略仍需独立评审。不能假定 `WaitGroupContext`、etcd 成员过期或 Mongo 条件更新已经独立保证全局只有一个业务执行者，不将此待决策能力提前作为当前存储方案的承诺。

### 可选存储 backend

RedisJSON/ReJSON、SQL 和其他存储后端不进入当前主线。评审时必须先确认目标云服务支持、本地测试方式、分片路由、部分读写收益和运维成本；通用 Store、`change.Source` 和变更文档契约不能依赖具体后端。

### 可选业务工具替换

`util.EventBus` 和 `util.DelayQueue` 是面向业务的可选工具。只有候选成熟库完整覆盖现有并发、顺序、取消和 transactional async 语义，并通过回归与 benchmark 后才替换；不能因为 tx runtime 当前未直接引用而删除。

## 明确不做

- 不在 tx 内实现分布式事务、跨实例锁或 Redis/Mongo 原子双写。
- 不为 Fusion 热写与延迟任务发布增加同槽持久交接索引、启动全槽扫描或容量闸门；进程存活期由本地去重重试和结构化错误日志保障任务发布。
- 不允许 Fusion 根记录物理删除；业务使用状态字段逻辑删除。
- 不把 Store、StoreView、变更文档声明为业务协议字段。
- 不把 Actor 与 GD、Store、Procedure 或持久化 Runtime 强绑定。
- 不在普通持久化链路重新引入字符串路径变更批次或操作重放日志。
- 不为尚未确定的 backend、协议或运维能力保留无效配置。
