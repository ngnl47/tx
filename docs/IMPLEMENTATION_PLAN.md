本文只记录当前阶段结论、尚未完成的工作及需要重新决策的方向。2026-10-10 根据当前源码、已提交变更和阶段报告核对；本轮不代表重新运行历史验收。

- 公共 API、配置和业务示例以根目录 [README](../README.md) 为准。
- 内部职责、状态机、固定术语和技术选型以 [设计文档](design.md) 为准。
- 架构质量要求以 [审计标准](architecture_audit_standard.md) 为准；特定版本的证据保存在 `docs/audits/`。
- 历史报告中的“下一项”、旧路径、临时准入阈值只适用于报告当时版本，不直接成为当前待办；已完成步骤不在此逐轮累积。

## 当前阶段结论

当前没有已确认、必须接着实施的框架编码项。NATS 迁移、异步上下行、服务装配收敛和 txgame 等级榜示例已完成本阶段工作；后续围绕具体业务接入问题或部署要求建立任务，不以扩大抽象、增加测试数量或寻找更细吞吐极限为目标。

| 方向 | 已完成状态与依据 | 仍需区分的边界 |
| --- | --- | --- |
| 实体与通信 | 本地 Actor 宿主、Discovery 稳定归属、Core NATS Actor RPC 已接线；ProtoActor 后端和 `internal/actortrial` 已移除。见 [NATS 整合记录](audits/2026-09-20-nats-integration-closeout.md)及 design 的 Actor 章节 | ProtoActor Provider 的历史关闭竞态不再作为当前后端风险；不承诺 RPC 异常必达或自动重投 |
| 上下行 | Agent→业务 Actor `CallStream`、业务服务→MsgQ `PublishStream`、Agent↔MsgQ `MailboxStream`，上下行不经 NATS | Agent 本地检查游标，每次上行提交及客户端 Ack 异步同步 MsgQ；没有 Agent Rec lease，不等待远端逐项成功回执 |
| 会话与关闭 | 旧角色归属明确未入邮箱时的单次重寻址、原 Session 恢复、新登录隔离、历史发布流错误不阻断最终关闭均已收口。见 [本地验收](audits/2026-09-28-local-stream-failure-acceptance.md)与 [feature 收尾](audits/2026-09-29-feature-closeout.md) | 本次排水中新发生的失败仍返回错误；历史故障流清理成功不表示消息已送达；不增加跨 Agent 上行 fencing |

| 服务装配与业务接入 | tx 管理通用能力、依赖闭包与生命周期；txgame 在各 `services/<name>` 注册服务，由项目入口选择进程组合。已提供可选 FightRoom、强类型房间 RPC、应用契约测试。见 [txgame 使用说明](../../txgame/README.md) | 四个基础节点不限制业务扩展；项目服务命名和组合不回收到 tx 内核 |
| Redis 与排行榜 | Redis 按名称选择单 backend，业务经薄封装使用原生命令；等级榜按成绩和达成时间排序，共享展示资料通过本地事件异步更新、批量 MGET 装饰。见 txgame README 及其提交 `348ef38`、`dec6607` | 分片、迁移及跨槽 MGET 由云 Redis 代理提供；榜单展示资料不是权威 GD，不自动回源或补偿 |

## 尚未完成：部署验收

以下有明确验收目的，但需要部署环境和业务参数；当前不自动租赁实例或启动云端测试。

1. **长期稳态与真实故障域**：在最终实例配置下验证持续负载、滚动更新、MsgQ/Redis 故障及恢复。沿用业务完成率与端到端延迟口径，同时观察 CPU、内存、队列和客户端计划发起延迟；不以短窗口通过替代长期容量结论。
2. **JetStream 生产配置**：确定实际磁盘、同步策略、副本与物理故障域，验证发布确认、重启恢复和通知流容量。现有 R1 强杀与同机三容器 R3 证据保留，不重复宣称为宿主掉电或跨机容灾。死信补偿和重投必须由业务决定，不能从“收到死信”推导业务未执行。
3. **会话积压容量**：继续使用两套示例的 1024 条/8 MiB 限额；在有实际慢客户端、离线时长和消息大小分布后评估容量。既有触限行为不是待实现项，不为测量新增无界缓冲或自动丢弃后继续会话的机制。

## 待决策方向

下列事项不是当前已承诺的实现计划。进入实施前先明确需求、职责和验证方式；不增加占位配置或兼容接口。

### 外部业务配置生成

txgame 当前使用项目维护的类型化配置最小契约；txgameslg 的 Login 列表从项目资产加载。扩展 txgen 前需明确 Excel 输入、类型推导、JSON 输出与加载契约；两套示例分别生成和维护，不相互引用。

### 控制面认证与 TLS/mTLS

现有内部通信可显式选择 TLS credentials 或本地 insecure；生产身份、权限、证书加载与轮换需要独立设计。保持业务投递、排水和槽位交接 API 的职责稳定，不将公网管理能力默认暴露。

### 异常接管与部署自动化

当前稳定归属支持受控排水与 generation CAS 交接，默认 1024 分区和业务 SlotMapping SPI 均已实现；世界支持独立槽位与实例容量上限。这些不是未来占位能力。

异常宕机、网络分区下自动接管，以及开服自动扩容、Pod 调度与世界交接编排仍需业务和运维方案。Mongo 版本检查不等于跨实例唯一执行者；成员过期也不能单独授权新旧实例同时执行。运行中单实体热迁移、远程脚本平台当前无需求，不启动建设。

### 存储与生成器扩展

- getter 仍只读内存；隐式懒加载必须先确定 loader 所有权、错误返回及 Actor/Procedure 并发边界。
- RedisJSON/ReJSON、SQL 等新 backend 需先确认真实业务需求、云产品能力及维护成本，不让通用 Store/变更文档依赖具体后端。
- Go 匿名嵌入字段深层代理、数值原子增量等生成扩展在 [txgen 计划](../../txgen/docs/IMPLEMENTATION_PLAN.md)单独维护，不与本轮 TypeScript 编码对齐混为一项。
- 排行榜分页、多种排名规则、资料删除/重建与真实军团玩法按具体业务提出；当前等级榜和展示事件契约不扩展成通用业务平台。

### 可选业务工具替换

`util.EventBus` 已用于 txgame 的共享资料事件；`util.DelayQueue` 仍是可选业务工具。只有存在具体问题、候选成熟库满足所需并发与生命周期契约时才评审替换，不因未被 runtime 使用或代码较短而删除。

## 持续维护约束

这些是后续改动的验收范围，不是要求持续增加测试或优化的任务。

- 以 txgame/txgameslg 为应用契约验收工程：保留项目规则、资源生命周期和关键真实后端验证，不复制 tx 内部故障矩阵。框架和生成器变更按受影响范围检查六工程，不能以单工程通过代替跨工程契约验证。
- 生成变更从输入和模板修正并重新生成，不手改产物。字段、Store、Provider 变更核对两套 GD；TypeScript/BON/Frame/Seq/Ack 变更核对两个客户端。
- 新缺陷先复现，修复验证关键状态转换。保留真实错误，未知投递结果不伪装成功、不盲目重投；功能通过与 race、真实依赖启用、生产容灾分别报告。
- 热点优化只在可复现瓶颈或明显维护成本出现时启动，使用同负载 profile/benchmark；不恢复已收敛的 GD 加载、生成器耗时或上下行细步长极限搜索。
- 历史 S01–S99 瘦身与旧基础验收已收敛，证据见 [整体收益复核](audits/2026-09-11-ponytail-overall-benefit.md)与 [基础能力矩阵](audits/2026-09-11-p0-foundation-plan.md)。旧版本问题不能不经核对直接转成当前 P0。

## 明确不做

- 不在 tx 内实现分布式事务、跨实例业务锁或 Redis/Mongo 原子双写。
- 不新增 Fusion 同槽交接索引、启动全槽扫描或完成表；沿用已接受的本地 pending 与异常窗口边界。
- 不允许 Fusion 根记录物理删除；业务使用状态字段逻辑删除。
- 不把 Actor 与 GD、Store、Procedure 或持久化 Runtime 强绑定，不把 Store/StoreView 生成成业务协议字段。
- 不在 tx 内重新引入 Redis 应用层分片、扩容迁移或客户端上行自动重放。
- 不为已退役 ProtoActor、旧同步会话链路或尚未确定的 backend 保留兼容层。

## 每轮完成条件

1. 公共行为更新 README，内部职责更新 design，本计划只维护真实待办和必要阶段结论。
2. 文档、GoDoc、注释和模板使用中文及固定技术术语。
3. 运行 `git diff --check`；代码改动执行受影响工程测试，涉及热点、存储或传输时追加相应证据。纯文档修改核对源码、链接与前后描述，不强行重跑集群。
4. 区分本轮实测、引用的历史证据和未验证项；不删除失败记录来得出通过结论。
5. 完成变更复核，按项目提供中文 Angular Commit Message；未明确要求不执行 Git commit。
