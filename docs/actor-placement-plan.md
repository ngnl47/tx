# 通用 Actor 放置能力

本轮不提交。目标是由目标服务声明分组策略，tx 统一处理查询、缓存、连接与本地/远程装配。业务只返回稳定分组 ID；服务池、策略名与分组 ID 组成框架槽位，跨 Actor Type 共享，同服务池内保证同实例。

## 实施与验收

1. Actor Type 引用服务内命名放置策略；Ant/Bee 在服务声明中提供策略工厂。工厂只在本进程选中提供方且 CMod 就绪后执行，先于业务服务启动。不增加调用方绑定。
2. tx 托管普通进程级 Placement 查询、65536 项有界缓存、同身份冷查询合并和 3 秒查询上限；复用已有 RPC Sender。缓存和实际执行中的查询纳入生命周期，失败不缓存、不回退或自动重投。
3. txgameslg 只保留 MainServer 分组解析及既有 GD/预留查询。删除专用 RPC、Router、缓存和 Agent/World 绑定。默认分区及 World 固定槽位保持不变。
4. 测试跨类型同组、不同服务/策略隔离、本地/远程自动装配、缓存与取消排水；启用本地依赖回归，并验证缓存命中零分配。

## 边界与取舍

- 新分组槽位使用框架编码，不能与旧 slggame-<ID> 混合上线；SLG 已要求停服迁移，测试工具同步使用框架编码函数。
- 不实现跨服务部署亲和、运行期改变分组或在线合服。策略工厂不承载独立后台资源。
- 仅启用消费者时不得构造目标服务的业务依赖；所有调用入口及加载前权威检查使用同一放置管线。

## 合服前置边界

Actor 放置是通用能力：项目提供分组，tx 负责槽位、查询缓存和稳定 owner。合服规则、目录修改与业务屏障均不进入 tx；项目合服执行示例后置。分组运行期稳定，同槽交接不修改分组，也不自动迁移业务数据。

新增 `TestPlacementGroupHandoffKeepsIdentityCache` 使用真实本地 NATS/etcd，验证三个类型共享一个槽位、本地与跨实例 Call，以及交接后复用 Identity→SlotID 缓存访问新 owner。
