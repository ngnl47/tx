# EntityCache 观察与管理实施计划

依据：2026-10-29 用户确认的最小方案；本轮不提交、不跑云压测、不增加管理页面。沿用当前工作区前七批未提交成果。

## 契约

在既有 Runtime 增加 Stats、List、SnapshotCached、TryRelease。统计不读取业务字段；列表有界且无稳定分页承诺；管理快照只命中，不触发加载、不更新淘汰热度；使用生成 Clone 在记录锁内复制。回收仅尝试一次，复用自动回收的持久化安全判定，不刷盘、不删除记录、不卸载 Actor。

EntryRef 为 Runtime 与驻留代次关联的不可构造引用，不持有 GD、不延长使用期。旧引用不能操作同 ID 新对象。公开管理快照/回收拒绝事务上下文，业务仍用既有 Find/Snapshot。

管理准入独立于业务准入。排水关闭新快照/回收并等待已接纳操作结束，元数据观察保留至最终关闭；超时不提前释放。不能阻断已准入业务在排水中的 GD 操作。

## 步骤与验收

1. 固定统计/列表、快照隔离/只命中、旧引用和安全回收测试，再实现缓存管理与统一回收核心。
2. 补管理准入/排水/关闭测试，接入框架关闭与惰性创建路径；不在业务热查询增加管理计数。
3. 生成 Descriptor 补类型名，重新生成两组工程；用真实生成 GDRole 验证 WriteBack pending 保留及快照，不为应用增加缓存登记。
4. 核心/生成器/两组应用本地回归与 race；同机相同参数运行前后热路径基准，保留原始结果，不推断云端容量。
5. 更新 API 文档、示例与验收范围，独立变更级复核，不提交。

## 具体取舍

- Stats 仅返回条目数量、待回收数量和现有配置，不增加命中计数、访问时间或内存估算。
- List 默认 100、最多 1000 条，类型筛选最坏 O(N)；结果是弱一致管理视图，不返回业务字段或可变内部结构。
- 快照复制不可被 context 强制中止；取消等待后仍须实际复制完成才释放。
- WriteBack 只提供 bool/error 安全判定，因此拒绝回收返回 Retained，不猜测具体脏状态。
