# 单机 2,000 会话长尾定位：Agent P2/P4/P2

2026-09-25 在新租的腾讯云 8 vCPU、16 GiB、Ubuntu 24.04 单机上复用正式 `txgame` 服务和 `txclient` TCP Ping/Pong。Login、Agent、MsgQ、Game 各运行一个独立进程；Redis、Mongo、etcd、NATS 使用固定版本容器，宿主机端口仅绑定 `127.0.0.1`。客户端也运行在同机，故本结果只用于定位单机链路和进程并行度，不能外推为四机容量或公网延迟。

服务端由本轮工作区源码在云机用 Go 1.27.0 构建，`-tags txbench` 仅提供显式诊断入口；前三轮没有启用服务端 pprof 或 gRPC Binary Log，也没有开启 `recLeaseInterval`。客户端使用 Node 26.0.0 和当前 `txclient`，两个 worker、每 Session 最多四条在途。2,000 个角色在正式窗口前全部登录、建立 TCP 会话，SessionID 唯一。每轮先预热 2 秒，再以每 Session 10 次/s 测量 60 秒，预期上下行各 1,200,000 条。前三轮只使用客户端现有阶段抽样、`pidstat` 和 `vmstat`；每轮测试角色归属自然释放后再继续。

| Agent | Login/MsgQ/Game | 上下行各完成 | 未发送 | 端到端 P50/P95/P99 | 到 Handler 前 P99 | Handler 后 P99 |
| --- | --- | ---: | ---: | --- | --- | --- |
| P2 首轮 | 均 P2 | 1,199,987 | 13 | 40.1/86.5/113.9 ms | 81 ms | 47 ms |
| P4 对照 | 均 P2 | 1,200,000 | 0 | 4.8/21.4/31.6 ms | 21–22 ms | 15 ms |
| P2 复测 | 均 P2 | 1,196,112 | 3,888 | 62.1/440.2/481.8 ms | 429–432 ms | 80–81 ms |

三轮已发送请求均零业务失败，所有已完成 Ping 都收到对应 Pong。16 会话冒烟先完成 1,600/1,600，P99 0.68 ms。P2 首轮的 13 条未发送都发生在正式窗口截止边界；P2 复测有约 3,290 个计划槽位因每会话四条在途达到上限而跳过，另有约 598 条在截止时仍待发送。P2 复测前 30 秒的到 Handler 前 P99 约 78–81 ms，后 30 秒升至约 416–452 ms，表现为积压而非单个固定延迟。

正式窗口内 Agent 平均 CPU 占核约为 P2 首轮 1.87、P4 2.22、P2 复测 1.88；对应 Game 约 1.18/1.28/1.22 核，MsgQ 约 0.92/1.04/0.94 核。整机平均空闲约 33.9%/27.7%/29.9%，steal 均为 0。两个客户端 worker 的事件循环利用率约 48%–49%，P99 停顿约 13–15 ms；它们均没有接近单核饱和。P2→P4→P2 的回退使长尾和未发送重新出现，因此本档最强的限制证据是**单个 Agent 的 P2 并行上限**，不是整机 CPU、MsgQ P2、Game P2 或客户端供给先触顶。P4 只多使用约 0.35 个 CPU 核，却明显缩短到 Handler 前的排队时间；不能据此断言某一个 `Rec`、Actor `Call` 或 TCP 写入函数是唯一根因。

代码路径也没有一个固定大小的“按 ConnectID 投递协程池”：TCP 每条连接独立运行 `Serve`，该连接的上行循环依次执行 `Rec`、Actor `Call`、`FrameAck`；下行 `StreamFetch` 由同 Session 的写入 goroutine 接收。P2 限制的是 Agent 进程可同时运行的 Go 计算，不是会话数或 goroutine 数。客户端阶段时间只把长尾分到 Handler 前后，不能继续从这些分位数中拆出 `Rec`、直连 `Call` 和写帧各自的排队时间，也不能相减两个 P99 当作单跳耗时。

原始 `client.json`、两 worker 的延迟与阶段样本、`pidstat`、`vmstat`、准备身份以及源码快照保存在工程外的 `tx-artifacts/cloud-20260925-single-host/`。云端结果压缩包 SHA-256 为 `6db2416cda37dec1d2fbf65d45811bacabb9fe6b9c075f00078e34b80c475982`；源码快照 SHA-256 为 `88c974a1c3bb773c4c68420f729bf7b3514186ac67cead3fac3dfafc434746f3`，云端服务二进制为 `5fc7e37a78ef993a1fcce59581f043dedbb0bbfb144105d5d5517a6197aa4f24`。这些结果均使用本轮未提交代码；不把历史压测当成当前验证。

## 同机直连长流对照

沿用上述不含 `txbench` 的同一服务二进制、四个独立进程各 P2、2,000 个 TCP 会话×10 次/s、30 秒正式窗口；每轮重建专用夹具。仅在 Agent 的隔离资产副本中设置 `directCallStream: true`，`directCallBatch` 始终关闭；MsgQ、Game 和 Login 使用原资产。顺序为 Unary→Stream→Unary，再独立复测一次 Stream。客户端、服务实例数、宿主机、Ping/Pong 业务和请求量不变；未启用 pprof、阶段计时或 Binary Log。

| --- | ---: | ---: | ---: | ---: | ---: |
| Unary 首轮 | 600,000 | 0/0 | 20.40/62.86/81.38 ms | 1.83 核 | 0.93/1.17 核 |
