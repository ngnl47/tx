# Mongo 超时迟到写入验证

## 结论与范围

客户端超时不能取消已发出的数据库请求。真实 Mongo 传输延迟对照中，旧写入 110 可以在新写入 120 成功、重试任务完成之后抵达，最终覆盖为 110。单机串行锁与失败重入不足以阻止这种迟到覆盖。

Fusion 生产路径采用：获取既有记录锁 → 读取 Mongo 版本 → 读取 Redis 最新文档 → 条件替换 Mongo 并递增版本。失败沿既有任务重试从头执行，不缓存版本、不保存操作标识或第二份业务快照。

Mongo 内部仅增加 `_tx_version`。没有部署所有权字段，不要求 GD 附加字段。首次创建使用插入和记录标识唯一索引；已有文档使用禁止 upsert 的版本条件替换。不能混入绕过版本条件的 Mongo 写入。

`_tx_version` 是框架保留的顶层 BSON int64，直接解码，不做嵌套元数据转换。切换已有数据时必须停写并迁移版本字段，不提供双格式兼容，也不能把已有版本误判为零。扁平字段相对嵌套版本每条减少 10 字节原始 BSON；实际磁盘收益取决于压缩。扁平字段本地增量基准三轮中位数 1.073ms、约 17.9KB/231 次分配，测试规模仍为每轮 100 次。

## 复现与回归

```sh
TX_MONGO_LATE_WRITE_ADDRESS=127.0.0.1:27017 go test -race ./storage/mongo/mongodriver -run TestMongoLateWriteAfterClientTimeout -count=3
```

七组场景包含无保护对照、Mongo 条件增量更新的迟到请求与确认丢失，以及 Fusion 已有文档迟到请求、已有文档确认丢失、首次创建迟到请求和首次创建确认丢失。三轮竞态检查通过，受保护场景最终均保持 120；无保护对照仍复现 110。增量场景还验证未修改字段保持不变。Fusion 场景使用实际生产 Handler、Scheduler、Redis 适配器和 Mongo 条件替换接口。

代理等待完整 Mongo 响应确认旧写执行结束，不以固定睡眠作证据。使用独立临时 Mongo 数据库与 Redis DB 15 的唯一测试记录，只清理明确的测试键。任务 backend 使用内存实现以推进调度时刻；这不是多进程租约验收，也不代表正常网络的故障发生频率。

有状态示例另外验证 Procedure 经 Fusion 的 10 秒周期写回及关闭最终写回。GDRole 的 `delaySaveTime:"1"` 用于快速示例验证，不作为生产周期建议；本轮不改 GD 注解或回写频率。

## 成本与职责

正常后台 Mongo 落地从一次写入变成一次元数据读取加一次条件写入。Redis 热写及 Procedure 变更合并不增加 I/O。可使用 `BenchmarkFusionMongoVersionedReplace` 比较同等持久化确认下的 Mongo 部分成本，不应把本地测量推广为生产吞吐结论。

本地 Intel i9、每组 100 次、三轮中位数：普通替换 0.522ms、版本预读加条件替换 1.092ms，增加约 0.570ms；分配约 8.1KB/128 次变为 18.8KB/263 次。两组均使用 majority 加 journal 确认，仅测 Mongo 部分，不含 Redis 或完整业务请求。此开销位于低频后台落地，不改变 GD 配置周期。

世界专用持久化接口已移除；槽位信息仅保留在路由校验中，数据库只验证文档版本。

世界示例真实多进程验收已通过（2026-09-09，`cluster-e2e --timeout 4m`）：包含双 Agent、双 MsgQ、双 Login、世界进程异常退出后接管、MsgQ 重启和角色服务晋升，最终业务数据落地与旧版本拒绝均通过。该项不是世界吞吐基准。

2026-09-10 以顶层 `_tx_version` 运行 `cluster-e2e --shutdown-failure --timeout 6m`，结果 passed。Mongo validator 持续拒绝世界写回，首次关闭及三次重试均记录一个待写根对象，四次失败分别发生于 00:05:58、00:06:14、00:06:30、00:06:46；随后输出重试耗尽及未落地数据可能丢失日志，世界进程以退出码 1 结束。解除阻塞后新实例接管，业务坐标落地，文档版本为 1，旧版本条件写入被拒绝。

验收目录：`/private/tmp/tx-shutdown-version-e2e/20260910-000447.203512000`。成功后按原验收归属标记清理专用存储范围，保留本地日志。该测试证明失败保留、有限重试及恢复边界，不承诺强制退出时内存变更不丢失；本轮没有修改运行时代码或新增测试用例。

## 独立 Mongo 增量路径进度

Adapter 与 Cluster 已提供 `ApplyVersionedChanges`：临时读取持久化版本，再生成当前字段级 `$set/$unset`，同次条件更新中推进版本。记录不存在时返回错误，不把更新隐式变成创建；冲突返回调用方，下一轮重新取得基线。首次记录创建沿用单独创建流程。

通用 storage runtime 已将 Mongo 普通更新接入 `VersionedChangeApplier`，不支持该接口的后端明确报错，不能静默回退无条件更新；显式 Upsert 仍沿原路径处理。健康检查与后端错误观察保持在统一入口。世界示例已直接复用通用 Writer，验收分别验证 assignment 切换及 Mongo 文档版本，不再将两种版本绑定。

独立 Mongo 增量基准每组 100 次、三轮中位数：普通增量 0.557ms、条件增量 1.115ms；分配约 7.8KB/107 次与 18.5KB/247 次。本地存在波动，不代表生产吞吐。此数据测量存储适配器，不包含 runtime 分派或完整 Procedure 链路。
