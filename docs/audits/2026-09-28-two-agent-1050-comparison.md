# 万连 10/50 双 Agent 与单 Agent 同日对照

## 条件

2026-09-28 使用腾讯云 SA9 8 核 16 GiB 实例。原接入机 `172.21.16.5` 运行 Login×2（各 P4）和 Agent×1（P8）；新增 `172.21.16.12` 只运行第二个 Agent（P8）。Game×2、MsgQ×2 仍各为 P4，分别留在原游戏机和存储机；独立客户端机不变。四台业务机的二进制 SHA-256 均为 `e9f09c12640657d69bb5d07e083c5b584c5bd85e89cbc135ee9946ab0cf784fe`。本地旧压缩缓存与该哈希不符，新 Agent 最终使用从原接入机复制并校验的同版二进制。

两轮都重置专用夹具，使用 10,000 个真实 TCP 会话、16 个客户端 worker、500 连接/s、每会话每秒 10 条 Ping、每条 Ping 五条下行、`max-in-flight=4`、2 秒预热和 180 秒正式窗口。先运行双 Agent，随后停止它并运行单 Agent 对照。每轮均独立创建角色；正式轮开启每进程 `/metrics`，约 5 秒抓取一次，没有启用 pprof 或逐消息诊断。16 会话冒烟先验证了两台 Agent 各承接 8 个连接，160 条上行与 800 条下行全部完成。

## 结果

| 配置 | 会话分配 | 最终完成 / 计划 1,800 万 | 未发送 | 窗口上行 / 下行 | 客户端 P99 |
| --- | --- | ---: | ---: | ---: | ---: |
| 同日单 Agent | 10,000 | 17,729,635（98.4980%） | 270,365 | 98,476.65 / 492,383.25 次/s | 569.68 ms |
| 双 Agent | 5,000 + 5,000 | 17,774,590（98.7477%） | 225,410 | 98,724.94 / 493,624.72 次/s | 209.44 ms |

两轮实际发出的上行最终全部完成，业务失败均为零；单 Agent 有 3,838 条、双 Agent 有 4,100 条在正式截止后完成。`status=failed` 表示最终完整处理率未达当前 99.99% 验收线，并非已发业务请求执行失败。双 Agent 的客户端 P99 比同日单 Agent 低约 63%，但窗口上行吞吐仅高约 0.25%，不能称为线性扩容，更未达到万连 20/50 目标或 10/50 的 60 ms P99 目标。

## 分段观测与判断

| 指标 | 单 Agent | 双 Agent |
| --- | ---: | ---: |
| Agent CPU | 7.70 核 | 4.21 + 4.20 核 |
| Agent 上行分派直方图 P99 | 约 177.95 ms | 约 3.24 / 3.25 ms |
| Agent 下行 Socket 写入直方图 P99 | 约 0.22 ms | 各约 0.09 ms |
| 客户端机正式区间空闲率 | 约 1.4% | 约 3.2% |
| 客户端机平均可运行进程数 | 约 17.9 | 约 17.0 |
| MsgQ 两进程 CPU 合计 | 约 3.76 核 | 约 4.72 核 |
| Game 两进程 CPU 合计 | 约 4.03 核 | 约 5.41 核 |

Agent 的 CPU、上行与下行处理量在双 Agent 轮中近乎均分；每台约处理 4.94 万上行和 24.68 万下行/s。分派 P99 是按指标桶内插值得到的估计，包含目标解析与写入目标流，不等于端到端延迟。MsgQ 发布及 Game 流提交的分段 P99 都约 0.01–0.02 ms，已采集的相关错误增量为零。上述 CPU 取正式窗口约第 5–178 秒的进程 CPU 增量；客户端机数据取其 `vmstat` 前 180 个有效秒样本，采样起点靠近窗口开始，存在数秒偏差。

这组同日对照支持：新增 Agent 显著缓解了单 Agent 接近 P8 上限时的分派排队和端到端长尾。它没有证明服务端容量只增加 0.25%；两轮客户端发生器都几乎吃满 8 核、平均可运行进程数约为核心数的两倍，计划请求在客户端尚未发出。单一 180 秒配对实验也不代表长期稳态或所有负载。此前跨日单 Agent 同版轮 P99 约 404 ms，与本次同日对照的 570 ms 不同，更说明应优先使用本次相邻轮比较方向，不把单次绝对值当生产容量。

下一步若要判断双 Agent 的服务端上限与是否接近 20/50，需要增加**独立客户端发生能力**，保持真实 TCP 链路及三分钟窗口，再看完整率、P99 和各节点 CPU。当前证据不支持继续增加 Agent 或按单机剩余 CPU 推算线性吞吐；更不应为了这个档位写死合批参数。
