# 六机 20/50 下行同帧时间分段

延续[上一轮 TCP 队列复核](2026-09-28-tcp-queue-client-read.md)的六机拓扑：两台 Agent 各 P8，两个 MsgQ、两个 Game 均 P4，两台客户端各 5000 条 TCP 会话。正式窗口 60 秒，每会话每秒计划 20 条上行，Ping 产生平均 50 条下行。MsgQ、Game、Login 和业务协议沿用原部署；两台 Agent 使用当前工作区的 `txbench` 诊断构建，客户端包增加同帧标识及接收时间。它不是与上一轮严格同版的性能 A/B，结果只能用于定位时间段。

诊断版仅对 `RoleID % 32 == 0` 且 `DownSeq % 8 == 0` 的帧记录 Agent TCP 写调用起止 Unix 微秒；客户端仍每 64 次计划请求抽样，并在原始 `onFrame` 边界记录 `RoleID`、`DownSeq`、Game 的 `Pong.serverTime` 和本机到帧时间。按角色和下行序号逐条匹配，得到 A/B 客户端各 370/390 条同帧样本；分别有 2641/2515 条客户端样本未命中 Agent 的二级抽样，这是预期的采样缺口。Agent 侧共记录 60,729/59,955 行。四台时间采样主机的 `chronyc tracking` 当时显示系统时间偏差约 0.05–0.48 ms，明显小于本文讨论的几十毫秒尾部；仍不能把跨机时间差当成微秒级精确测量。

两侧计划完成率约为 99.870% / 99.785%，**未达到 99.99%**；未发送是客户端错过计划时隙，不是已发送业务请求丢失。上一轮相同拓扑的未发送为 21,544/2,727，完整请求 P99 为 105.99/82.84 ms。本轮两个客户端的完整请求 P99 更高，但上线诊断版后没有无探针对照，不能将变化单独归因于探针。

同帧分段如下，P99 仅分别对应约四条最高样本，应以 P95 和高尾计数为主要判断依据：

| 同一 Pong 的时间段 | A P50 / P95 / P99 | B P50 / P95 / P99 |
| --- | ---: | ---: |
| Game 创建 Pong→Agent TCP 写调用结束 | 5.69 / 23.30 / 34.90 ms | 5.84 / 23.90 / 43.46 ms |
| Agent TCP 写调用本身 | 0.006 / 0.024 / 1.032 ms | 0.006 / 0.023 / 3.104 ms |
| Agent TCP 写调用结束→客户端原始帧回调 | 0.96 / 33.39 / 66.07 ms | 1.59 / 23.35 / 42.21 ms |
| Game 创建 Pong→客户端原始帧回调 | 8 / 46 / 75 ms | 10 / 35 / 69 ms |

同帧 `Game 创建→客户端帧` 达到 50 ms 的 A/B 样本分别为 13/8 条；其中 `Agent 写出→客户端帧` 单段就达到 50 ms 的有 11/3 条，而 `Game 创建→Agent 写出` 单段达到 50 ms 的有 0/1 条。按 Agent 来源进一步拆分，客户端 A 从 Agent A/B 接收的写出后 P95 分别约 16/42 ms，客户端 B 从 Agent A/B 接收的分别约 24/23 ms；A 的尾部在两台 Agent 上均出现，支持客户端侧因素参与，但样本量不足以排除链路和内核队列。

Prometheus 结束时直方图按同名实例汇总的 P99 桶上界：Agent TCP 写调用 0.25 ms、Agent Mailbox 接收队列 10 ms、Game Actor 邮箱等待 60 ms、Game→MsgQ 发布流排队 20 ms、MsgQ 邮箱发送队列 5 ms。直方图是各自的抽样分布，**不能把这些 P99 相加**。`Pong.serverTime` 在 Game Handler 内创建，位于 Actor 邮箱等待之后，因此上表的同帧“Game 创建→Agent 写出”不包含 Actor 入邮箱前的上行排队。完整请求 P99 变高与 Game Actor 邮箱 P99 桶升至 60 ms 同时出现，但尚未建立同一请求的上行阶段因果。

本轮把后半段长尾定位到 **Agent 成功调用 TCP 写入之后、客户端原始帧回调之前**，尤其是客户端 A；不能再把该部分解释成 Agent→Game 共享流的发送锁等待。上一轮客户端 Recv-Q 非零和事件循环延迟与长尾相关，本轮客户端逐秒事件循环 P99 中位数约 26.85/27.37 ms，支持继续调查客户端读取调度。不过 `Write` 返回只代表数据交给本机内核，仍需客户端内核收包时间才能在网络/TCP 队列与 Node 读取调度之间划界。Game Actor 邮箱等待也是另一条需要独立追踪的前半段路径；不据此调高流数或固定合批阈值。

原始压缩包、六个进程的指标快照、同帧 CSV、分析脚本与汇总位于工作区 `tx-artifacts/cloud-20260928-dual-client/same-frame-20260928/`。压测后已按 Agent/Login→Game→MsgQ 顺序停止业务进程并清理专用夹具，中间件容器保持原状。
