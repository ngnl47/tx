# I3l：稳定分服与分战区映射 SPI

用户确认默认使用 1024 分区，同时要求业务可声明稳定分服/分战区规则；当前不需要运行中单实体热迁移。本轮保留上轮全部未提交变更，仅修改 tx，不提交 Git。

## 实现及边界

公开 `actor.SlotMapping` 函数型 SPI：输入 Identity、输出稳定槽位。未提供映射时走已有 v1 1024 分区，显式映射结果不会再取模，也不会因结果为空而回退。现有归属入口负责拒绝空槽位。

`SlotMapping.Resolve` 是唯一默认选择入口，替代路由、首次分配和加载校验中分别选择默认规则的代码。现有显式世界映射继续适用。测试使用公开类型声明一份业务函数，再由内部组合根绑定给这三处；正式 Kind 自动装配还未迁入，不能宣称当前 NewKind 已接受这个 SPI。

示例中角色 1、2 默认会使用各自哈希分区，稳定业务规则则让它们共同返回 `role-zone-10`。同战区共用 owner，各角色仍有独立状态和邮箱。真实业务可使用一致的稳定业务目录或身份编码推导分组；不能依赖仅某个 Session 携带的临时信息，也不能修改目录来绕过正常归属交接。

自定义槽位须带业务命名空间，避免不同 Kind 意外合并；保留 `actor-v1.` 前缀给默认规则。一个分组必须能由单实例承载，容量不足不自动拆组。
