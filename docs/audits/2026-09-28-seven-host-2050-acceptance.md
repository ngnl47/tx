# 当前异步长流方案：七机万连 20/50 回测

2026-09-28 使用当前直连异步长流链路：Agent→Game `CallStream`、Game→MsgQ `PublishStream`、Agent↔MsgQ `MailboxStream`。服务端部署在四台 8 核 16 GiB 云主机：一台运行 Login×2、Agent×1，另一台运行 Agent×1，Game×2 和 MsgQ×2 各占一台；Agent 为 P8，Game、MsgQ、Login 为 P4。三台独立客户端发生器分别承载 3334/3333/3333 条 TCP 会话，均使用 Node v26.0.0 与相同构建，角色区间合计覆盖 10,000 个角色；建连总速率约 500/s。预热后同时运行 180 秒，每会话计划每秒 20 条上行，`System_Ping` 平均产生 50 条下行。该负载只验证客户端上下行，不代表 Core NATS Actor RPC 或 JetStream 任务吞吐。执行脚本位于 `tx-artifacts/cloud-20260928-publish-ab/run-three-clients.sh`；三轮原始结果分别位于同目录的 `publish-ab-three-clients-20260928/`、`publish-ab-three-clients-repeat1-20260928/`、`publish-ab-three-clients-repeat2-20260928/`。脚本保留当时云实例地址，仅作为复现参数记录。

合计计划完成率 **99.999919%**，上、下行完成吞吐分别约 **199,994/s** 和 **499,983/s**。三台客户端的会话最终恰好均分到两台 Agent，各 5000 条。本轮满足当前万连 20/50 的 99.99% 处理率与客户端 P99 低于 60 ms 的三分钟验收口径；单轮结果不能证明所有时段的生产容量。

测量窗口的进程 CPU 增量：两台 Agent 为 1126.05/1133.79 核秒，Game 两进程为 561.41/564.27 核秒，MsgQ 两进程为 468.65/469.14 核秒。按 180 秒粗算，Agent 各约占 6.3 核，Game 各约 3.1 核，MsgQ 各约 2.6 核；这只是进程 CPU 均值，不表示瞬时峰值或宿主机独占容量。Agent 上行分派的抽样 P99 桶上界均为 20 ms，Game Actor 邮箱等待为 10/20 ms，下行发布流本地队列等待均为 10 ms，底层 `Send` 均为 0.01 ms。指标中发布流、RPC 提交和下行写错误均为 0；三台客户端标准错误日志为空。

三台客户端的 `runner.js`、主代码分块和 Node 可执行文件 SHA-256 分别完全一致；主代码分块为 `b4d8e8aeeb0ab2bedc17720e806f0cb0bb79379eac2cebcf5cb80181b507603f`。这说明现有四台服务机配置在该三分钟窗口达到目标；客户端机器不计入生产服务扩容收益。生产配置仍需同版负载下的故障恢复与更长稳态验证，并观察 Agent 瞬时 CPU 与分派排队。
