# 生成模型与导入组装性能对照（2026-09-10）

前半部分记录 S07–S09 的首次性能验证；S10–S11 的后续对照及当前状态见文末。

## 结论与处置

原未提交 S07 的 Store 导入列表逐步追加存在分配字节退化，已调整。保留 RecordKey 整份列表构造，只合并反射、事务和最终返回的重复尾部；保留 S08 的 Data 分支收敛及 S09 的标准库拼接。

例如无 time、带 RecordKey 的普通 Store，从 HEAD 的 1288 B/op 增至原工作区的 1784 B/op（+38.5%），修正后恢复 1288 B/op；分配次数为 20 → 19 → 20。分配次数下降不代表内存分配成本一定降低。

这是微基准发现的具体退化，不是生产吞吐退化证据。完整生成初次对照未确认整体耗时退化；最终版本仍需结合下面的测量范围和波动解读。

## 基线与采集边界

- txgen HEAD：`065ff002c3ae8dd6e40942eb7e4ad614928b7945`；原工作区包含 S07–S09。S06 只改 txgameslg 的测试参数查找，不进入生产路径，本次不为它跑集群吞吐压测。
- Go 1.27.0，darwin/amd64，Intel Core i9-9880H；两边固定 `GOMAXPROCS=1`，不将单机单 P 结果解释为生产容量。测试和构建使用同一 `/private/tmp/tx-go-build`。
- 通过 Go `-overlay` 将 HEAD、原工作区、单独 S07 和修正版本分别编入临时二进制。微基准源码也只通过 overlay 注入，不向工程添加基准文件或生产钩子。
- 微基准用 `testing.B.Loop`、`ReportAllocs` 和包级结果接收变量，覆盖 time/RecordKey/reflect/transaction/extra 的 32 种 Store 组合及 8 种 Data 组合。每版每组合 6 次、每次 50ms，串行交错版本顺序；表中均为中位数。
- 单独 S07 变体重现 1288 → 1784 B/op，确认该项不是 S08 或 S09 引起。修正版本 40 个组合的 B/op 和 allocs/op 中位数均不高于 HEAD。
- 最敏感的普通 RecordKey Store 额外进行 10 轮交错、每次 300ms 的复测：HEAD 2107.5ns（2055–2153），修正版本 2115.5ns（2078–2238），中位数 +0.4%，分布重叠；不能据此证明所有输入耗时严格不增加。
- 完整生成使用预编译入口和临时输入副本，包含扫描、渲染、格式化及写文件，不包含 Go 编译。每场景两版各预热一次，再交错测量 8 轮；每次运行后核对输出文件名与内容 SHA-256。没有并发运行构建、测试或其他本任务压测。
- 原始日志、源码快照、overlay、基准及采集脚本保存在 [临时证据目录](/private/tmp/tx-import-perf-20260910)。该目录可能被系统清理；本报告保留主要结果与方法。构建过程中出现模块缓存只读提示，但所有构建均退出 0，未改 go.mod/go.sum。

## S11：Store 复用已构建的 RecordKey

基线为 txgen `e63eaea59213bf3dbbc2786a05a19fca43dbe3e4`（S10 已提交）。Store 构建先调用 Data 模型构建，后者已保存 RecordKey；原路径随后重复构建同一结果。现直接使用 `data.RecordKey`，没有跨请求缓存或公开接口，也不改变构建输入。

Data 模型构建只读取类型定义；随后 Store 使用局部 Data 模型的字段和键模型，不再修改该局部键模型。文档字段名列表由原构建函数创建，未引入对输入切片的共享写入。

| 真实类型 | 原 ns/op | 新 ns/op | 原 B/op → 新 B/op | 原 allocs/op → 新 allocs/op |
| --- | ---: | ---: | ---: | ---: |
| fixture/GDArenaRecord | 36846.5 | 37465.5 | 26057 → 25313 | 318 → 312 |
| fixture/GDItem | 9259.0 | 9178.5 | 5488 → 5488 | 83 → 83 |
| fixture/GDRole | 39226.0 | 38123.5 | 28577 → 27897 | 353 → 349 |
| txgame/GDArenaRecord | 56493.0 | 55845.0 | 30265 → 28929 | 433 → 427 |
| txgame/GDRole | 334425.5 | 328015.0 | 206453 → 201485 | 2269 → 2265 |

六个有 RecordKey 类型均减少分配；无 RecordKey 的 GDItem 分配不变。fixture/GDArenaRecord 初测中位数约 +1.7%，另以 10 轮交错、300ms 加长复测：原 35701ns（35093–44793），新 35263.5ns（34010–37744），未重现耗时退化。保留两组结果，不将初测和复测混为同一组样本。
