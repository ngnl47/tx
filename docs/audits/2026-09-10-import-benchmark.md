# 生成模型与导入组装性能对照（2026-09-10）

前半部分记录 S07–S09 的首次性能验证；S10–S28 的后续对照及当前状态见文末。

## 结论与处置

原未提交 S07 的 Store 导入列表逐步追加存在分配字节退化，已调整。保留 RecordKey 整份列表构造，只合并反射、事务和最终返回的重复尾部；保留 S08 的 Data 分支收敛及 S09 的标准库拼接。

例如无 time、带 RecordKey 的普通 Store，从 HEAD 的 1288 B/op 增至原工作区的 1784 B/op（+38.5%），修正后恢复 1288 B/op；分配次数为 20 → 19 → 20。分配次数下降不代表内存分配成本一定降低。

这是微基准发现的具体退化，不是生产吞吐退化证据。完整生成初次对照未确认整体耗时退化；最终版本仍需结合下面的测量范围和波动解读。
