# JetStream 同步策略对照

本轮只采集数据并补充部署取舍，不修改生产代码、测试入口或默认配置。接续 [固定到达率记录](2026-09-20-jetstream-task-arrival.md)，验证本机强同步下的积压是否随同步策略变化，不以降低持久性来宣布 tx 优化成功。

## 实验与结果

基线提交 `c68a876`；Go 1.27.0 darwin/amd64、GOMAXPROCS=4、NATS 2.14.6、nats.go 1.53.1。同机 Docker 三节点、独立容器可写层 `/data`，不是生产持久卷；沿用 32 个热 Actor、256B payload、4 发布者和 4 消费回调、内存计数业务。200 条/s 固定计划到达，每窗口 5 秒、1000 条；每组 R1/R3 各三轮。配置切换时停止再启动同一组容器，三个节点同步修改；每个窗口新建文件流和 durable，其副本数一致。

按 A1 `always` → B `2m` → A2 `always` 串行采集。[原始 18 窗口 JSON](baselines/2026-09-20-jetstream-task-sync.json) 保留全部指标、镜像摘要和启动失败信息。下表为三轮指标中位数；不是合并样本 P99。

| 阶段 | 副本 | 计划到达→完成 P99 ms | 开始发布延误 P99 ms | 窗口末未完成 | 其中未开始 | 额外排空 ms |

| A1 always | R1 | 34.30 | 0.30 | 1 | 0 | 2.76 |
| A1 always | R3 | 2923.46 | 2829.68 | 369 | 361 | 2929.86 |

18000 条正式采集任务全部执行并确认；逐条核验投递次数为 1、无重复完成、业务计数一致，源流最终清空。三组测试分别通过（39.76s、31.08s、52.48s）。未完成数包含发布者本地尚未开始的任务，不是 Broker 队列长度；指标口径与命令沿用固定到达率记录，设置 `TX_TASK_RATE=200`。

切为周期同步后 R3 的发布落后明显下降，切回强同步后重新出现，支持同步策略是本环境的重要影响因素。A1/A2 数值仍有明显波动，不能宣称稳定加速倍数、唯一瓶颈或特定磁盘设备根因。计划速率被固定在 200 条/s，不能据此推断周期同步的最大吞吐。每个性能窗口只有 5 秒，未覆盖完整 2 分钟同步周期的长期稳态、周期刷盘尖峰或故障恢复；没有真实 GD、数据库及跨物理机负载。

## 持久性取舍

NATS 官方说明：文件写入后通常先进入操作系统缓存，默认同步间隔为 2 分钟；`always` 在确认前逐次同步。R3 的副本多数派确认不等同于每份数据均已完成物理落盘，周期同步下仍存在系统故障造成已确认数据丢失的窗口。不能将 `2m` 解释为任务等待两分钟才被消费，也不能将这次正常运行测试解释为掉电验收。[官方持久性说明](https://github.com/nats-io/nats.docs/blob/master/nats-concepts/jetstream/README.md)、[同步配置](https://github.com/nats-io/nats.docs/blob/master/running-a-nats-service/configuration/README.md)。

例如，奖励任务取得 PubAck 表示当前策略下完成发布确认，业务完成仍由消费适配器等待 Actor 结果后 ACK。若采用周期同步，宿主故障可能影响尚未同步的已确认记录；tx 不增加完成表或 GD 回放来填补这一部署取舍。

建议保留 `always` 作为当前保守验收基线，先明确可靠任务所需速率及可接受丢失窗口，再决定生产同步策略和存储部署。不能仅凭本机周期同步跑分快而默认降低可靠性。下一项需要决策的是生产候选同步策略及目标任务负载；目标环境尚未确定前，不继续围绕本机 fsync 现象做细碎代码优化。真实业务、长期稳态与物理故障域验收继续保留。

## 启动异常与现场

B 首次尝试在 12:14:29 启动测试，Broker 日志显示 12:14:32 才选出元数据 leader；`CreateStream` 最终在 180.02s 超时（测试第 120 行），未产生性能窗口。期间原生 `$JS.API.STREAM.NAMES` 已可成功返回空列表。现象与选主前资源请求未收到响应一致；SDK 该调用使用传入 Context deadline，本轮没有将它修改为生产自动重试。

后续 B 和 A2 在元数据 API 成功后才启动测试，均通过。复现时须先确认 JetStream 元数据请求可用，不能只以 TCP 可连接或容器 Running 作为就绪条件。失败启动不纳入性能样本，也不作为业务任务丢失证据。

失败 etcd 范围 `/tx/tests/task-baseline/QRC2VGUXZCF32NVESBSH4NKHOP` 保留；成功运行各自资源已按测试归属清理。本轮网络 `tx-task-baseline-29dbd97f` 和三个容器保留且已停止，配置与三节点日志位于 `/var/folders/gq/xxck3g710bq4w3q85kq21jfm0000gn/T/tx-task-baseline-29dbd97f`。后续配置回切不保留原进程内存，启动异常日志已留存；共享 NATS 和此前失败现场未修改。
