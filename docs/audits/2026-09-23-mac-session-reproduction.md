# Mac 会话失效复现与准备阶段检测修复

接续[Agent 并行度对照](2026-09-23-agent-parallelism.md)。本轮按用户要求只在 Mac 上运行，不更新云端部署、不执行 Git commit。原云端 347 条断连的服务端根因尚未定位，不能将客户端检测修复称为原故障修复。

## 已复现并修复的问题

压测准备阶段只给 connected 端点发送保活。已建立的连接在其他角色登录期间关闭后，会被保活过滤掉，但仍可能出现在 ready 身份列表中；直到预热才暴露 `AgentClient 尚未连接`。

通过两角色测试，在第二个角色登录时主动关闭第一条连接，修复前仍写出 ready，回归断言失败。txclient 现在监听准备阶段的 closed 状态，记录 RoleID/SessionID，取消 start 文件等待并使本轮失败；不自动重连、不延长超时、不补发业务。准备阶段保活失败也会取消等待。进入预热后结束这项准备阶段监听的有效期，连接清理由现有 dispose 处理。

例如角色 480100 在准备期间断开，将报告 `准备阶段连接关闭：role 480100, session ...`，不会继续将该轮计为成功准备。ready 文件只是当时的身份清单，并不承诺写出后连接持续在线。

两项回归分别覆盖写 ready 前断开、等待 start 文件时断开；前者完成红→绿验证。修复范围仅为旁路压测 CLI，不修改生产客户端协议或服务端会话语义。

## 本地真实链路

使用现有 txgame 正式服务、正式登录和 Ping/Pong，Login、Agent、MsgQ、Game 各两进程，每进程 GOMAXPROCS=2；依赖使用本地 Docker Redis/Mongo/etcd/NATS。压测隔离资源为 Redis DB12、Mongo `txgame_cluster_e2e`、etcd `/tx/e2e/txgame`。

复用云端配置并替换为回环地址，保持原 10 分钟租期和 30 秒离线期限；仅打开 debug 日志。64 角色、两个客户端进程、总建连速率 10/s、每会话 1/s、预热 2 秒、单请求超时 5 秒。按首次登录 30 秒→等待归属自然释放→重新登录并持续 12 分钟→等待释放→再次登录 30 秒执行，各轮之间不重启服务、不清库。

该规模用于复现生命周期，不是容量验收，也没有模拟云端万连准备阶段的全部时序。12 分钟正式窗口会跨过最初租期，并观察两次半租期续期；抽样记录首尾两个角色及 Session 的 Redis 值和剩余 TTL，不能把两个抽样扩大为全部会话的逐条续期证据。

首次启动脚本曾误用 Login 的 gRPC 端口作为就绪探针，Login 不监听该端口而退出编排；八进程均正常停止。修正为控制端口后重新准备隔离夹具启动，不能把此编排错误解释为 session 故障。
