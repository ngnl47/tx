# 接入服务持续流量滚动发布验收

本轮按[验收计划](session-rollout-acceptance-plan.md)运行两组本地普通正式包。每组依次替换一个 Login、Agent、MsgQ，每窗 180 秒、40 连接、每连接 5 次/秒，TCP 与 WebSocket 各半。生产运行时、协议和自动恢复策略未修改，不跑云测试、不提交。

后续定位补充：旧客户端也会把 Ready 前普通关闭转换成 `HandshakeRejectedError`，因此本报告中 TCP 的恢复通过只是当时工具判定，不能作为明确应用拒绝的证据。后续修复改为明确结果帧，并对 TCP/WebSocket 一起补验；见[接入拒绝修复与补验](session-rejection-acceptance-20261104.md)。本页原始计数和失败记录保留。

## 统计与证据边界

每窗固定计划数 36,000，最多允许 3 个未完成请求才达到 99.99%。断连及恢复期间不暂停计划，不补发错过请求，不重投结果未知的上行。已发送完成率不能替代全部计划完成率。

```text
36,000 计划请求 = 未发送 + 成功完成 + 已尝试但失败
客户端流量结算 → 独立恢复判定 → 正常排水和进程退出 → 持久化读回
```

受影响组和对照组在准备期固定，各 18,000 计划。新登录、离线通知、最终标记改名和 World 控制探针不进入流量分母。SLG 最终改名是独立业务确认，不是只读查询；Mongo 读回另行判定。

## 本轮发现及修正

本轮实际运行暴露三处验收工具缺口，均保留原始失败记录；没有以修改生产行为或放宽断言解决：

1. txgame 账号夹具只创建角色投影，有限会话验收走握手后 Ping。新端点多发 `Role_Enter`，导致开始计时前被建角准入拒绝。删除多余初始化，补充握手后仅发业务探针的回归。
2. Agent 停止后已从进程表删除，发布工具仍无条件读取它的日志，造成 nil 指针。日志起点只供 MsgQ 恢复拒绝取证，两组改为仅在 MsgQ 窗口采集。修复后的真实 Agent 窗口正常结算。
3. SLG World 完成通知的 `gridId=0` 会被正式 BON 编码省略，新工具直接比较 `undefined` 与 0 而超时。沿用已有有限工具的零值处理，测试先复现超时再通过；不修改生成产物或客户端解码协议。

## 尚未通过的恢复边界

两组 MsgQ 窗口均出现相同结果：20 个受影响连接的 TCP 一半完成旧邮箱拒绝和重新登录，WebSocket 一半报告传输错误。Agent 日志可看到相同 SID 的 `session instance is unavailable`，但客户端不能据此把网络关闭解释为明确的应用拒绝。

当前 Agent WebSocket 关闭使用 `CloseNow`；验收端点在握手失败期间看到传输错误会保留失败。有限工具此前只抽取一个丢失会话，不等于覆盖了这批 WebSocket 会话。这里保留恢复失败，不在本轮扩大为生产协议改造，也不让网络错误冒充恢复契约通过。

恢复动作失败后，未恢复的连接继续贡献后续计划的“未发送”。因此 MsgQ 窗口的大量未完成请求包含这段持续不可发送时间，不能全部称为服务端丢消息，也不能用该窗口估算正常发布耗时。

## 持久化、退出与残留

- 最终两轮各 10 次服务退出，全部等待到真实退出、退出码 0、无排水错误。独立 `ps` 检查没有本轮验收进程残留；依赖容器保持运行。
- SLG Login、Agent 两窗各 40 个最终改名与两条 World 完成路径通过。正常排水后，工具实际核对了这 80 个角色的 Mongo 名称、RoleID、OriginServerID=1001。
- MsgQ 窗口恢复失败，未进入独立最终标记及 World 收尾，完整持久化报告明确失败：`窗口 msgq 缺少最终业务角色状态`。没有用前两窗的成功替代 120 角色完整验收。
- 独立只读复核再次确认前两窗 80 个角色全部一致；最后成功 World 移动的单位 1001 在世界 1、桶 7，Mongo 坐标为 (21,22)、文档版本 2，与 Agent 窗口确认相同。这只证明最后成功操作已保存，不证明缺失的第三窗最终操作。
- 失败现场按原工具规则保留：Redis DB12/13 分别 125/563 键，Mongo 专用库分别 6/8 个集合，etcd 专用范围分别 122/4 个键。etcd 没有实例注册残留，所有保留 assignment 的 owner 均为空；保留项是空闲槽位代次、发号键和 ownership 标记。未清空专用数据，更未触及其他数据库。

客户端结果中的 `cleanup=passed` 只表示客户端连接收尾成功，不表示失败现场的数据已清理。txgame 使用 Ping，不据此宣称本轮验证了角色 GD 写回。
