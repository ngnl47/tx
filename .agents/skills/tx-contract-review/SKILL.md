# tx 工程约定审查

## 定位范围与规则

- 先遵守用户指定工程、路径或 diff 范围及其 AGENTS.md；未指定时检查当前工程的暂存、未暂存和未跟踪文件。多仓库父目录先列出相关仓库状态，不把所有仓库自动纳入全量审计。
- 本 Skill 不保存业务规则、参数默认值或历史结论。读取 tx 仓库的 [工程约定](../../../docs/engineering-conventions.md)与 [审计标准](../../../docs/architecture_audit_standard.md)，再按所涉 EC 条目读取链接的契约。
- 上述链接以 Skill 的真实目录解析（安装可能是符号链接）。若复制后链接失效，从当前工作区、兄弟目录或应用 go.mod 的本地 replace 定位 tx；无法找到规则时说明缺失，不用记忆或互联网版本代替当前约定。

## 检查方法

1. 读取差异、调用者与能力所有者，确认生成输入/模板和产物的关系。无差异时如实说明，不擅自把“审查变更”改为全库扫描。
2. 对每条候选问题先确认适用范围：对象是否受管、谁持有它、ctx 属于哪个执行范围、资源由谁关闭、返回值确认到哪一步。不能仅凭 Find、Save、Background、go、Access 或 Scope 等关键词判错。
3. 按工程约定的适用路径核对，再追踪到实际状态转换或并发触发条件。文档与代码冲突要列明双方依据；不能机械以代码覆盖已确认契约，也不以旧文档要求恢复废弃方案。
4. 优先使用现有测试和可重现的静态调用链佐证。只读审查不编辑文件、不生成代码、不提交、不启动服务/容器或压测；需要执行有副作用的验证时报告所需步骤，由用户决定。测试未运行就标明未验证。

## 输出

复用审计标准的 P0～P3 分级和 findings 格式，不另设严重级别。每条包括：

- 文件和行号、EC 编号及对应契约链接；
- 具体触发路径、影响与证据，区分实测、静态推导和待确认；
- 最小修复方向；不借审查扩展重构范围。

先列可操作问题，再列重要的未覆盖项；同一根因合并报告，不以问题数量为目标。没有发现问题时说明检查范围和验证限制，不宣称全部正确。普通命名偏好、未证实的性能猜测不作为缺陷；修复另行获得授权。
